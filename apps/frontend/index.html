The EVM execution client built for operators.

Fukuii is an execution layer client in Scala 3. It runs Ethereum Classic and Mordor natively on proof of work, and follows Ethereum mainnet, Sepolia, Hoodi, Ephemery and Platåberget under any consensus client over the Engine API, from Prague through Osaka to Amsterdam.

What is Fukuii?

An independent execution client for ETC and Ethereum.

A continuation of Mantis, IOHK's Scala client, maintained by Chippr Robotics and modernised to Scala 3 and JDK 25. The goal: a credible non-Geth execution client for both Ethereum Classic and post-Merge Ethereum, on a JVM dependency tree with its own failure profile.

Two chain families, one binary

ETC and Mordor run proof of work with Ethash and block-number forks. Ethereum networks run proof of stake through the Engine API with timestamp forks. The two code paths are kept apart on purpose, and pinned by tests.

A command center in the terminal

Start with --tui for views of the chain, peers, mempool, RPC, Engine API, mining, storage and the host, with health bars, threshold alerts and operator actions from the same screen.

Broad API surface

JSON-RPC over HTTP, WebSocket and IPC, with eth_simulateV1, trace, txpool, GraphQL and an MCP server for AI agents, plus /health, /readiness and /buildinfo for your orchestrator.

Capabilities

What the client does today.

Sync, EVM forks, Engine API, JSON-RPC, verification, and the operational tooling around them — as shipped in the 0.12 release line.

SNAP sync, block import, and checkpoints

Fast sync is gone. ETC and Mordor SNAP-sync by default; the Ethereum networks follow their consensus client by importing blocks. Healing converges on a live chain without walking the whole state trie.

  • SNAP — snap/1 state download with every header validated against its parent, deepest-first healing that commits only complete subtrees, and a background audit after hand-off
  • Block import — the default on Sepolia, mainnet, Hoodi, Ephemery and Platåberget, driven by engine_newPayload and forkchoiceUpdated
  • Checkpoint bootstrap — ETC and Mordor nodes import a trusted pivot and start SNAP at once
  • Portable chain files — fukuii <network> export / import in go-ethereum's format
  • Wire — eth/68 and eth/69 everywhere; eth/70 and eth/71 on the Ethereum networks

Ethereum through Amsterdam, ETC through Olympia

Ethereum mainnet's schedule through Osaka and the BPO2 blob fork, and the Amsterdam execution rules of Glamsterdam, active on Sepolia and Platåberget. On ETC, Olympia is implemented and waits for the network to choose an activation block.

  • EIP-7928 block-level access lists
  • EIP-7843 SLOTNUM
  • EIP-8024 SWAPN / DUPN / EXCHANGE
  • EIP-8037 / 8038 state gas repricing
  • EIP-7778 gas accounting without refunds
  • EIP-7708 ETH transfers emit a log
  • EIP-7954 larger contract size
  • EIP-7976 / 7981 calldata and access-list cost
  • EIP-7840 / 7892 per-chain blob schedule
  • EIP-4844 blobs · EIP-7685 requests
  • ECIP-1111 EIP-1559 fee market for ETC
  • ECIP-1112 treasury · ECIP-1121 MESS

Engine API through Amsterdam

On by default for every chain that needs a consensus client, on localhost:8551. At first start fukuii writes a persistent secret to <datadir>/jwt.hex (mode 0600) for your consensus client's --execution-jwt.

  • engine_newPayloadV1..V5
  • engine_forkchoiceUpdatedV1..V4
  • engine_getPayloadV1..V6
  • engine_getPayloadBodiesByHash / ByRange V1 and V2
  • engine_getBlobsV1 / V2 · engine_getClientVersionV1 · engine_exchangeCapabilities

JSON-RPC, GraphQL, and MCP for AI agents

HTTP on 8546, WebSocket on 8552, and IPC, all bound to localhost by default. As in go-ethereum, HTTP and WebSocket serve only eth, net, web3 and fukuii until you opt in to more, per transport. Add mcp to a transport's list to expose a Model Context Protocol server (2025-11-25) to LLM agents.

  • eth_* incl. eth_simulateV1
  • net_* · web3_*
  • debug_*
  • trace_*
  • txpool_*
  • admin_*
  • miner_* (ETC)
  • personal_*
  • GraphQL

Health endpoints: /health · /readiness · /healthcheck · /buildinfo

What is gated, and what only reports

Fukuii publishes which checks can block a merge, generated from the CI gate matrix. Three are required today: the build with Tier-1 and Tier-2 tests, the Docker build, and the gate-integrity meta-check. Hive suites run and report but are informational — not a compliance claim until promoted.

  • EEST Amsterdam — 26,503 / 26,503 execution-specs blockchain tests replayed through block import, and every accepted block rebuilt by the payload builder
  • First required Hive slice — geth ↔ fukuii sync both ways, Engine API invalid-payload rejection, ETC-fork consume-rlp; target 2026-12-31
  • Also running — smoke, rpc-compat, graphql, devp2p, consensus, consume-engine, and nightly ethereum/tests across both fork schedules

Operations

Safe defaults, visible state.

Observability, predictable behaviour under load, and a verifiable artifact chain — the things that matter at 3 a.m.

Observability built in

Prometheus metrics across sync phases, peers and the Engine API, Grafana dashboards in the reference deployments, per-peer reliability scores, and health endpoints for orchestrators and load balancers.

Locked down by default

RPC and the Engine API bind to localhost. HTTP and WebSocket expose four namespaces until you opt in, WebSocket checks an Origin allowlist, and the Engine API accepts only HS256 JWTs.

Verifiable artifacts

Container images on GHCR are Cosign keyless-signed, with BuildKit provenance and SBOM attestations. Release archives ship with SHA256SUMS.txt.

Runbooks for first start, peering, disk, backup, log triage and known issues live in the operator documentation.

Get started

Pick your path.

Release archives need JDK 25+. Pin a release from GitHub Releases in place of <version>.

01

ETC / Mordor

Download a release and SNAP-sync the ETC testnet.

unzip fukuii-<version>.zip
cd fukuii-<version>

# datadir: ~/.fukuii/mordor
./bin/fukuii mordor --tui

# ETC mainnet: ./bin/fukuii etc
02

Docker

Cosign-signed images on GHCR. RPC stays on the host's loopback.

docker run -d --name fukuii \
  -p 30303:30303/tcp -p 30303:30303/udp \
  -p 127.0.0.1:8546:8546 \
  -v fukuii-data:/app/data \
  ghcr.io/chippr-robotics/fukuii:<version> \
  -Dconfig.file=/app/conf/etc.conf \
  -Dfukuii.datadir=/app/data \
  -Dfukuii.network.rpc.http.interface=0.0.0.0
03

Sepolia + CL

Engine API is on by default. Point any CL at the JWT fukuii creates.

./bin/fukuii sepolia
# Engine API: localhost:8551
# JWT: ~/.fukuii/sepolia/jwt.hex

lighthouse bn --network sepolia \
  --execution-endpoint http://localhost:8551 \
  --execution-jwt ~/.fukuii/sepolia/jwt.hex \
  --checkpoint-sync-url <provider>
